01
Visão Geral e Pré-requisitos

O FinOps Manager é uma aplicação Node.js + Express que serve uma SPA para gestão de custos Azure. O backend (server.js/app.js) não tem build step — os arquivos são servidos diretamente. O frontend está em migração incremental (strangler fig) de vanilla-JS para React: a maioria das telas hoje já é React (`frontend/`, bundle Vite), e ESSE bundle precisa ser compilado antes do deploy — ver aviso abaixo. O backend persiste dados em PostgreSQL (versão 14+).

Arquitetura
ComponenteTecnologiaObservação
BackendNode.js 18+ / Express 4Processo único; sem cluster; sem build step
Frontend (shell)Vanilla JSindex.html + app.js + styles.css — sem build step, servido direto (calculadora.js não é mais carregado por nenhuma página — código morto)
Frontend (telas)React + TypeScript + Vitefrontend/ — build obrigatório antes do deploy (gera frontend/dist/*)
Banco de dadosPostgreSQL 14+Único banco; schema criado automaticamente
AutenticaçãoJWT + bcryptSuporte a AD (LDAP) e Entra ID (OAuth 2.0)
Arquivos temporáriosuploads_tmp/CSVs deletados após importação
Build do frontend é obrigatório

Todo comando de instalação neste guia (Linux, Windows, Docker, VM, Railway, Render, Azure App Service) precisa rodar npm run frontend:build (na raiz do projeto) além do npm install de sempre. Esse comando compila o React (via Vite) e gera frontend/dist/react-app.js, frontend/dist/react-app.css e frontend/dist/portal-app.js — arquivos que index.html/portal.html carregam via <script type="module" src="/react-app/react-app.js">. Sem rodar esse build, a aplicação sobe, o login funciona, mas todas as telas migradas (Dashboard, Calculadora, Reservas, Ações, Coleta Azure, Estimativas, Projetos, Portal Público) ficam em branco — o navegador tenta baixar um arquivo que não existe (404) e não há erro visível óbvio além do console do browser. frontend/ (o código-fonte) tem seu próprio package.json/node_modules, separado do backend — rodar só o npm install da raiz NÃO instala as dependências do frontend nem gera o build.

Portas e protocolos
  • 3000/TCP — aplicação Node.js (entrada padrão, configurável)
  • 5432/TCP — PostgreSQL (acesso do Node ao banco)
  • 389/TCP ou 636/TCP — LDAP/LDAPS (opcional; apenas se usar AD)
  • 443/TCP — saída HTTPS para Azure APIs (coleta automática, Price List)
Mascote

O arquivo mascote.png não está no repositório git (está no .gitignore). Copie-o manualmente para o diretório da aplicação após o clone. Sem ele, a tela de login exibe apenas o logo SVG "vivo" — sem erro funcional.

02
On-Premises — Linux
On-Prem

Procedimento testado em Ubuntu 22.04 LTS, Debian 12 e RHEL/AlmaLinux 9. Comandos idênticos; substitua apt por dnf no RHEL.

1. Instalar Node.js 20 LTS
# Ubuntu / Debian
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# RHEL / AlmaLinux / Rocky
curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash -
sudo dnf install -y nodejs

# Verificar
node -v && npm -v
2. Instalar PostgreSQL 16
# Ubuntu 22.04
sudo apt install -y postgresql postgresql-contrib
sudo systemctl enable postgresql --now

# Criar banco e usuário
sudo -u postgres psql <<'SQL'
CREATE USER finops_user WITH PASSWORD 'SenhaForte123!';
CREATE DATABASE finops_db OWNER finops_user;
GRANT ALL PRIVILEGES ON DATABASE finops_db TO finops_user;
SQL
3. Clonar e instalar dependências
# Criar usuário de sistema dedicado (boa prática)
sudo useradd -r -s /usr/sbin/nologin -d /opt/finops finops

sudo git clone https://github.com/seu-org/finops-manager.git /opt/finops
sudo chown -R finops:finops /opt/finops

sudo -u finops bash -c "cd /opt/finops && npm install --production"

# Build do frontend React (obrigatório — sem isso as telas migradas ficam em branco)
sudo -u finops bash -c "cd /opt/finops && npm run frontend:install && npm run frontend:build"
4. Configurar variáveis de ambiente
# Gerar segredos
node -e "const c=require('crypto'); console.log('JWT_SECRET='+c.randomBytes(48).toString('hex')); console.log('MASTER_KEY='+c.randomBytes(48).toString('hex'));"

# Criar .env
sudo -u finops tee /opt/finops/.env <<'EOF'
JWT_SECRET=<cole aqui o JWT_SECRET gerado acima>
MASTER_KEY=<cole aqui o MASTER_KEY gerado acima>
DB_HOST=localhost
DB_PORT=5432
DB_NAME=finops_db
DB_USER=finops_user
DB_PASSWORD=SenhaForte123!
PORT=3000
ALLOWED_ORIGIN=https://finops.suaempresa.com.br
JWT_EXPIRES=8h
EOF

sudo chmod 600 /opt/finops/.env
5. Encriptar .env (recomendado para produção)
# Gera .env.enc + .env.key (AES-256-GCM)
sudo -u finops bash -c "cd /opt/finops && node encrypt-env.js encrypt"
# Guarde .env.key em local seguro; remova .env após confirmar que encrypt funcionou
sudo -u finops rm /opt/finops/.env
6. Configurar PM2 (recomendado)
sudo npm install -g pm2

# Iniciar aplicação
sudo -u finops bash -c "cd /opt/finops && pm2 start server.js --name finops-manager"

# Persistir entre reinicializações
pm2 save
sudo pm2 startup systemd -u finops --hp /opt/finops
Alternativa — systemd direto

Se preferir não usar PM2, consulte a seção de serviço systemd no README.md do projeto ou configure manualmente em /etc/systemd/system/finops-manager.service.

7. Configurar nginx como proxy reverso (HTTPS)
# /etc/nginx/sites-available/finops
server {
    listen 80;
    server_name finops.suaempresa.com.br;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl;
    server_name finops.suaempresa.com.br;

    ssl_certificate     /etc/letsencrypt/live/finops.suaempresa.com.br/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/finops.suaempresa.com.br/privkey.pem;

    # Necessário para upload de arquivos CSV grandes (até 2 GB)
    client_max_body_size 2048m;
    proxy_read_timeout   600;
    proxy_send_timeout   600;

    location / {
        proxy_pass         http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection keep-alive;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }
}
# Certificado Let's Encrypt gratuito
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d finops.suaempresa.com.br
Firewall

Libere apenas as portas 80 e 443 externamente. A porta 3000 deve ficar acessível somente localmente (127.0.0.1). Exemplo: sudo ufw allow 80/tcp && sudo ufw allow 443/tcp

03
On-Premises — Windows Server
On-Prem

Compatível com Windows Server 2019 e 2022. Utilize o PowerShell como Administrador para todos os passos.

1. Instalar Node.js 20 LTS

Baixe o instalador MSI em nodejs.org (versão 20 LTS 64-bit) e execute. Após a instalação, abra um novo PowerShell e verifique: node -v

2. Instalar PostgreSQL 16

Baixe o instalador em postgresql.org/download/windows. Durante a instalação:

  • Porta: 5432 (padrão)
  • Senha do superusuário: defina e anote
  • Marque "pgAdmin 4" para interface gráfica
# Via psql (PowerShell), criar banco e usuário
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -c "CREATE USER finops_user WITH PASSWORD 'SenhaForte123!';"
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -c "CREATE DATABASE finops_db OWNER finops_user;"
3. Clonar repositório
# Instalar Git caso não tenha: https://git-scm.com
git clone https://github.com/seu-org/finops-manager.git C:\finops
cd C:\finops
npm install --production

# Build do frontend React (obrigatório — sem isso as telas migradas ficam em branco)
npm run frontend:install
npm run frontend:build
4. Configurar variáveis de ambiente
# Gerar segredos (execute 2x — um para cada variável)
[System.Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(48))

# Criar arquivo .env em C:\finops\.env
$env = @"
JWT_SECRET=<gerado acima>
MASTER_KEY=<gerado acima>
DB_HOST=localhost
DB_PORT=5432
DB_NAME=finops_db
DB_USER=finops_user
DB_PASSWORD=SenhaForte123!
PORT=3000
ALLOWED_ORIGIN=https://finops.suaempresa.com.br
"@
$env | Out-File -FilePath "C:\finops\.env" -Encoding utf8
5. Instalar como serviço Windows com NSSM

Baixe o NSSM em nssm.cc e coloque em C:\nssm\nssm.exe.

C:\nssm\nssm.exe install FinOpsManager
C:\nssm\nssm.exe set FinOpsManager Application  "C:\Program Files\nodejs\node.exe"
C:\nssm\nssm.exe set FinOpsManager AppDirectory "C:\finops"
C:\nssm\nssm.exe set FinOpsManager AppParameters "server.js"
C:\nssm\nssm.exe set FinOpsManager Start SERVICE_AUTO_START
C:\nssm\nssm.exe set FinOpsManager AppStdout "C:\finops\logs\app.log"
C:\nssm\nssm.exe set FinOpsManager AppStderr "C:\finops\logs\error.log"
New-Item -ItemType Directory -Force C:\finops\logs
C:\nssm\nssm.exe start FinOpsManager
6. Firewall e IIS como proxy reverso (opcional)
# Abrir porta 3000 no Firewall do Windows (se acesso direto)
New-NetFirewallRule -DisplayName "FinOps Manager" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow

# Para usar IIS como proxy reverso, instale o módulo ARR (Application Request Routing)
# e configure um site apontando para http://localhost:3000
IIS como Proxy

O IIS pode ser configurado como proxy reverso usando o módulo ARR (Application Request Routing) com URL Rewrite. Consulte a documentação Microsoft para detalhes. Alternativamente, use o Caddy Server para Windows — mais simples e com HTTPS automático.

Cloud IaaS — Docker
IaaS

A imagem Docker pode ser usada em qualquer provedor cloud (AWS ECS, Azure Container Instances, GCP Cloud Run, Kubernetes) ou em Docker Engine local/on-premises.

Dockerfile

Build em dois estágios: o primeiro compila o frontend React (precisa do node_modules completo do Vite/TypeScript, que não deve ir para a imagem final); o segundo monta a imagem de produção só com o backend + o resultado já compilado (frontend/dist/).

# ── Estágio 1: build do frontend React ──
FROM node:20-alpine AS frontend-build
WORKDIR /app/frontend
COPY frontend/package*.json ./
RUN npm install
COPY frontend/ ./
RUN npm run build

# ── Estágio 2: imagem de produção ──
FROM node:20-alpine
WORKDIR /app

COPY package*.json ./
RUN npm install --production

COPY . .
# Substitui o frontend/ copiado acima (que não tem dist/) pelo build do estágio 1
COPY --from=frontend-build /app/frontend/dist ./frontend/dist

# Diretório para uploads temporários e dados persistentes
RUN mkdir -p uploads_tmp

EXPOSE 3000
CMD ["node", "server.js"]
Build e execução
# Build da imagem
docker build -t finops-manager:v2.4 .

# Executar com variáveis de ambiente e volume persistente
docker run -d \
  --name finops \
  --restart unless-stopped \
  -p 3000:3000 \
  -e JWT_SECRET="seu-segredo-aqui" \
  -e MASTER_KEY="seu-master-key-aqui" \
  -e DB_HOST="host-do-postgres" \
  -e DB_PORT="5432" \
  -e DB_NAME="finops_db" \
  -e DB_USER="finops_user" \
  -e DB_PASSWORD="SenhaForte123!" \
  -e ALLOWED_ORIGIN="https://finops.suaempresa.com.br" \
  -v finops-data:/app \
  finops-manager:v2.4
Volume persistente

O volume finops-data persiste o arquivo .finops_setup (configuração inicial), mascote.png e uploads_tmp/. Sem o volume, cada reinicialização do container exigirá refazer o wizard de configuração inicial.

docker-compose.yml (completo)
version: '3.8'
services:
  finops:
    image: finops-manager:v2.4
    restart: unless-stopped
    ports:
      - "3000:3000"
    environment:
      JWT_SECRET: ${JWT_SECRET}
      MASTER_KEY: ${MASTER_KEY}
      DB_HOST: postgres
      DB_PORT: 5432
      DB_NAME: finops_db
      DB_USER: finops_user
      DB_PASSWORD: ${DB_PASSWORD}
      ALLOWED_ORIGIN: ${ALLOWED_ORIGIN}
    volumes:
      - finops-data:/app
    depends_on:
      postgres:
        condition: service_healthy

  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_DB: finops_db
      POSTGRES_USER: finops_user
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U finops_user -d finops_db"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  finops-data:
  pgdata:
# Criar arquivo .env com as variáveis
JWT_SECRET=seu-segredo-longo
MASTER_KEY=seu-master-key-longo
DB_PASSWORD=SenhaForte123!
ALLOWED_ORIGIN=https://finops.suaempresa.com.br

# Iniciar
docker compose up -d

# Verificar logs
docker compose logs -f finops

# Criar Resource Group e VM
az group create --name rg-finops --location brazilsouth

az vm create \
  --resource-group rg-finops \
  --name vm-finops \
  --image Ubuntu2204 \
  --size Standard_B2s \

# Abrir porta 80 e 443 (nginx)
az vm open-port --resource-group rg-finops --name vm-finops --port 80 --priority 900
az vm open-port --resource-group rg-finops --name vm-finops --port 443 --priority 901

# Criar PostgreSQL Flexible Server
az postgres flexible-server create \
  --resource-group rg-finops \
  --name finops-pg \
  --location brazilsouth \
  --version 16 \
  --admin-user pgadmin \
  --admin-password "SenhaForte123!" \
  --sku-name Standard_B1ms \
  --tier Burstable \
  --storage-size 32

az postgres flexible-server db create \
  --resource-group rg-finops \
  --server-name finops-pg \
  --database-name finops_db

# Obter string de conexão
az postgres flexible-server show-connection-string \
  --server-name finops-pg \
  --database-name finops_db \
  --admin-user pgadmin \
  --admin-password "SenhaForte123!" \
  --query connectionStrings.nodejs

Use o valor DATABASE_URL resultante no arquivo .env da aplicação, no lugar das variáveis DB_* individuais. Após isso, siga os passos 3 a 7 da seção On-Premises Linux.

Firewall do banco

No PostgreSQL Flexible Server, configure a regra de firewall para permitir apenas o IP privado (ou a VNET) da VM. Não exponha o PostgreSQL publicamente.

06
Cloud PaaS — Railway
Cloud PaaS

Opção mais simples para quem não quer gerenciar infraestrutura. O Railway detecta automaticamente o Node.js e injeta DATABASE_URL.

1

Acesse railway.app e faça login com GitHub.

2

Clique em + New Project → Deploy from GitHub repo e selecione o repositório finops-manager.

3

Ainda no projeto, clique em + New → Database → PostgreSQL. O Railway cria o banco e injeta DATABASE_URL automaticamente.

4

No serviço da aplicação, vá em Variables e adicione:
JWT_SECRET, MASTER_KEY, ALLOWED_ORIGIN

5

Em Settings → Build, defina o Build Command como npm install && npm run frontend:build (o Nixpacks do Railway só roda npm install por padrão — sem isso, o frontend React nunca é compilado e todas as telas migradas ficam em branco). Em Settings → Deploy, confirme que o Start Command é node server.js.

6

O Railway fará o primeiro deploy automaticamente. Acesse a URL gerada (ex: finops-manager.up.railway.app).

7

Para domínio customizado: Settings → Networking → Custom Domain.

Uploads grandes

O Railway tem timeout padrão de 60s para requests. Para importar CSVs grandes, pode ser necessário configurar RAILWAY_TIMEOUT=600 nas variáveis ou usar a coleta automática via Storage ao invés de upload manual.

Cloud PaaS — Render
Cloud PaaS
1

Acesse render.com e crie uma conta.

2

Crie um PostgreSQL: New → PostgreSQL. Anote a Internal Database URL.

3

Crie um Web Service: New → Web Service → conecte o repositório GitHub.
Build Command: npm install && npm run frontend:build (compila o frontend React — sem isso as telas migradas ficam em branco)
Start Command: node server.js

4

Em Environment, adicione as variáveis:
DATABASE_URL = Internal Database URL do passo 2
JWT_SECRET, MASTER_KEY, ALLOWED_ORIGIN

5

Clique em Create Web Service. O primeiro deploy inicia automaticamente.

Sleep no plano gratuito

O plano gratuito do Render suspende serviços após 15 minutos de inatividade. Para uso em produção, utilize pelo menos o plano Starter ($7/mês), que mantém o serviço sempre ativo.

Cloud PaaS — Azure App Service
Cloud PaaS

Solução PaaS totalmente gerenciada na Azure. Banco de dados via PostgreSQL Flexible Server (seção 5).

# Criar App Service Plan e Web App
az appservice plan create \
  --resource-group rg-finops \
  --name finops-plan \
  --location brazilsouth \
  --sku B1 \
  --is-linux

az webapp create \
  --resource-group rg-finops \
  --plan finops-plan \
  --name finops-manager \
  --runtime "NODE:20-lts"

# Configurar startup
az webapp config set \
  --resource-group rg-finops \
  --name finops-manager \
  --startup-file "node server.js"

# Definir variáveis de ambiente
az webapp config appsettings set \
  --resource-group rg-finops \
  --name finops-manager \
  --settings \
    DATABASE_URL="postgresql://pgadmin:Senha@finops-pg.postgres.database.azure.com:5432/finops_db?sslmode=require" \
    JWT_SECRET="seu-segredo" \
    MASTER_KEY="seu-master-key" \
    ALLOWED_ORIGIN="https://finops-manager.azurewebsites.net"

# Build do frontend React ANTES de zipar (obrigatório — gera frontend/dist/*)
npm run frontend:install
npm run frontend:build

# Fazer deploy via ZIP — exclui node_modules (raiz e frontend/), mas mantém frontend/dist
zip -r finops.zip . -x "node_modules/*" -x "frontend/node_modules/*" -x "frontend/src/*" -x ".env" -x "uploads_tmp/*" -x ".git/*"
az webapp deploy \
  --resource-group rg-finops \
  --name finops-manager \
  --src-path finops.zip \
  --type zip

# Acompanhar logs em tempo real
az webapp log tail --resource-group rg-finops --name finops-manager
Domínio e HTTPS

O Azure App Service provisiona automaticamente o domínio *.azurewebsites.net com HTTPS. Para domínio customizado, use Custom Domains no portal Azure e vincule um certificado (App Service Managed Certificate é gratuito para domínios customizados).

Upload de arquivos grandes

Por padrão, o App Service limita requests a 28 MB. Para importar CSVs maiores, aumente o limite via configuração WEBSITE_MAX_REQUEST_LENGTH ou use a coleta automática via Azure Storage (sem necessidade de upload).

Segurança

O servidor exibe um aviso no console de inicialização se JWT_SECRET ou MASTER_KEY estiverem com os valores padrão inseguros. Nunca suba para produção com os valores padrão. Use os comandos da seção 2 ou 3 para gerar segredos criptograficamente seguros.

Prioridade de configuração

O servidor carrega as configurações nesta ordem (maior prioridade primeiro):

  1. Variáveis de ambiente do sistema operacional / plataforma PaaS
  2. .env.enc + .env.key (arquivo encriptado — produção)
  3. .env (arquivo plain text — desenvolvimento)
  4. .finops_setup (configurações salvas pelo wizard de setup)

Configuração Inicial e Checklist de Produção
Wizard de configuração

Na primeira execução (sem arquivo .finops_setup), a aplicação serve apenas o wizard de configuração. Acesse a URL da aplicação e siga as etapas:

1

Conexão com banco de dados — preencha host, porta, banco, usuário e senha. Clique em "Testar conexão" antes de prosseguir.

2

Usuário administrador — nome, e-mail e senha do primeiro usuário. Este usuário terá perfil Administrador.

3

Autenticação opcional — configure AD (LDAP) ou Microsoft Entra ID se necessário. Pode ser pulado e configurado depois.

4

Concluir — o sistema grava .finops_setup (encriptado com MASTER_KEY) e reinicia os serviços. O wizard não aparecerá novamente.

Checklist de produção
Segurança

JWT_SECRET definido com string aleatória ≥ 32 caracteres

MASTER_KEY definido com string aleatória ≥ 32 caracteres e armazenado em cofre seguro

ALLOWED_ORIGIN definido com o domínio exato (sem wildcard)

.env.enc usado em vez de .env plain text (produção)

HTTPS configurado no proxy reverso (nginx / Caddy / App Service)

Porta 3000 acessível apenas em localhost (não exposta externamente)

Banco de Dados

PostgreSQL com senha forte (não padrão)

Backup automático configurado (pg_dump ou backup gerenciado do provedor)

Acesso ao banco restrito ao IP/VNET da aplicação

Aplicação

npm run frontend:build executado com sucesso — frontend/dist/react-app.js e frontend/dist/portal-app.js existem (senão, todas as telas migradas ficam em branco)

PM2 / systemd / NSSM configurado para reinicialização automática

Diretório uploads_tmp/ com permissão de escrita pelo processo Node

Arquivo mascote.png presente na raiz da aplicação

Wizard de configuração inicial concluído (.finops_setup existe)

Portal Público (se ativado)

subscription_ids configurados nas definições do Portal — sem isso, nenhum dado é exposto

solicitar_identificacao=true ou dominios_aceitos configurado para restringir acesso

Coleta Automática — Azure (se usada)

Service Principal criado no Azure com roles Reader + Storage Blob Data Reader nas subscriptions desejadas

Conexão testada com sucesso em Coleta Azure → Service Principals → Testar antes de agendar

Coleta Automática — Databricks (se usada)

Um Account Admin habilitou os schemas de System Tables (system.billing.*) em Catalog Explorer — não vêm habilitados por padrão em nenhuma conta

Credencial (Service Principal de conta em modo OAuth M2M, ou PAT de workspace) com USE SCHEMA + SELECT em system.billing.usage e system.billing.list_prices

Testar confirma cada System Table individualmente (não só o SQL Warehouse) antes de agendar a coleta

Para usar Quotas Genie: conexão em modo OAuth M2M marcada como padrão — PAT não tem escopo de conta suficiente para essa feature

Passo a passo detalhado

Este guia cobre a instalação e o deploy do servidor. Para o passo a passo de configuração da Coleta Automática (Azure e Databricks) dentro do sistema já em execução — criação de Service Principal, System Tables, agendamento, importação manual, Quotas Genie — consulte o Manual do Usuário (docs-usuario.html), Seções 10 a 14.

Comandos úteis pós-implantação
# Verificar sintaxe dos arquivos principais
node --check server.js
node --check app.js

# Confirmar que o build do frontend React existe e está sendo servido
ls -la frontend/dist/react-app.js frontend/dist/portal-app.js
curl -sI http://localhost:3000/react-app/react-app.js | head -1   # deve ser 200, não 404

# PM2 — monitoramento
pm2 status
pm2 logs finops-manager --lines 100
pm2 monit

# Verificar conectividade com banco
psql "postgresql://finops_user:senha@localhost:5432/finops_db" -c "SELECT version();"

# Checar tabelas criadas pelo servidor
psql "postgresql://finops_user:senha@localhost:5432/finops_db" -c "\dt"
