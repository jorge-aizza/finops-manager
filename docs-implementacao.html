01
Visão Geral do Sistema

O FinOps Manager é uma plataforma web de gestão de custos em nuvem desenvolvida para a Vivo. Permite acompanhar gastos Azure, criar projetos e ações de otimização, gerar estimativas de custos e gerenciar reservas de recursos cloud, tudo em uma interface unificada com tema visual Vivo.

Aplicação Single-Process · Sem build step · Serve arquivos estáticos diretamente

03
Instalação
Passos de Instalação
1
Transferir os arquivos para o servidor
Copie todos os arquivos do projeto para o diretório de destino (ex: /opt/finops-manager). Certifique-se de incluir .finops_setup caso já exista configuração prévia. As pastas fonts/ e libs/ fazem parte do repositório — não precisam ser baixadas separadamente.
2
Instalar dependências Node.js
Execute no diretório do projeto:
npm install
Fontes e biblioteca XLSX — self-hosted

A partir da v2.1, as fontes IBM Plex Sans/Mono (fonts/) e a biblioteca XLSX.js (libs/xlsx.full.min.js) já estão incluídas no repositório. Não é necessário nenhum passo extra — o npm install cuida apenas das dependências Node.js do servidor.

3
Copiar o mascote.png
O arquivo mascote.png (imagem do mascote Vivo na tela de login) não é versionado no Git. Copie-o manualmente para a pasta raiz da aplicação:
# Linux
cp /caminho/original/mascote.png /opt/finops-manager/mascote.png

# Windows (PowerShell)
Copy-Item "C:\origem\mascote.png" "C:\finops-manager\mascote.png"
mascote.png ausente

Se o arquivo não for copiado, a tela de login exibe apenas o logo SVG "vivo" em roxo. O sistema funciona normalmente — o arquivo é apenas visual.

4
Criar o arquivo de variáveis de ambiente
Crie o arquivo .env na raiz do projeto. Consulte a seção 04 para a lista completa de variáveis e como gerar os valores seguros.
5
(Recomendado) Criptografar o .env
Para ambientes de produção, gere o arquivo criptografado e remova o texto puro:
node encrypt-env.js encrypt   # gera .env.enc + .env.key
rm .env                       # Linux — apaga o texto puro
Remove-Item .env              # Windows PowerShell
6
Iniciar o servidor
Para produção, use um gerenciador de processos como PM2 (ver seção 12):
# Produção simples
npm start

# Com .env criptografado
node encrypt-env.js run

# Com PM2 (recomendado para produção)
npm install -g pm2
pm2 start server.js --name finops-manager
pm2 save && pm2 startup

# Desenvolvimento (hot reload)
npm run dev
7
Verificar a saúde da aplicação
Após o servidor iniciar, valide o endpoint de health check:
# Resposta esperada: {"status":"ok","db":"connected",...}
curl http://localhost:3000/health
Se retornar "db: unavailable"

O servidor subiu mas não conectou ao PostgreSQL. Verifique as variáveis DB_HOST, DB_PORT, DB_USER, DB_PASSWORD e DB_NAME. Confirme que o PostgreSQL está acessível a partir do servidor.

Como Gerar os Valores de JWT_SECRET e MASTER_KEY

Nunca use valores inventados manualmente. Utilize um dos comandos abaixo para gerar strings criptograficamente seguras:

Opção 1 — Node.js (recomendado — já disponível no servidor):

node -e "const c=require('crypto'); console.log('JWT_SECRET=' + c.randomBytes(48).toString('hex')); console.log('MASTER_KEY=' + c.randomBytes(48).toString('hex'));"

O comando imprime as duas linhas prontas para colar no .env.

Opção 2 — PowerShell (Windows):

# Execute duas vezes — uma para cada variável
[System.Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(48))
Regras Obrigatórias

· Mínimo 32 caracteres (os métodos acima geram 96).
· Nunca compartilhar o JWT_SECRET — quem o tiver consegue forjar tokens de login válidos.
· Se o MASTER_KEY for alterado após o setup, o arquivo .finops_setup não poderá mais ser lido. Guarde o valor em local seguro.
· O servidor emite aviso no console ao iniciar caso os valores padrão estejam em uso.

Setup Inicial e Banco de Dados
Primeiro Acesso — Wizard de Configuração

Na primeira execução, o sistema detecta a ausência do arquivo .finops_setup e exibe automaticamente o Wizard de Configuração. Nenhuma outra rota está disponível até a conclusão do wizard.

1
Acesse o sistema no navegador
Abra http://localhost:3000 (ou o domínio configurado). O wizard será exibido automaticamente.
2
Configure a conexão com o banco de dados
Informe host, porta, nome do banco, usuário e senha. O sistema testará a conexão antes de prosseguir.
3
Crie o usuário administrador
Defina nome, e-mail e senha do primeiro usuário com perfil admin. Este usuário poderá criar outros usuários posteriormente.
4
Conclusão automática
O sistema cria o arquivo .finops_setup (criptografado com AES-256-CBC), inicializa todas as tabelas e redireciona para o login.

Funcionalidades v2.1
📊
Dashboard
Visão consolidada de projetos, ações FinOps e custos cloud. Estatísticas por status, economia gerada e breakdown por nuvem. Atualização automática configurável (padrão 10 min).
📁
Projetos e Ações FinOps
Cadastro de projetos com responsável e prazo. Ações de otimização com status, economia estimada/realizada, cloud e prioridade. Exportação completa em Excel (3 abas).
☁️
Custos Azure
Visualização de gastos por subscription, resource group e período. Filtros avançados. Importação via CSV ou Parquet (Azure Cost Management). Suporte a arquivos de até 500 MB.
🧮

Seleção de recursos Azure por subscription/RG/período. Simulação de horas de uso com slider. Geração de estimativa em PDF. Validade fixa de 5 dias e motivo da solicitação obrigatório.
💰

Sincronização com Azure Retail Prices API (~100 mil SKUs). Coluna PL/h e badge de desconto real vs. on-demand na calculadora. Cobertura para hora, dia, periodo e reservas.

Coleta automática de custos Azure via Service Principals (sem upload manual). Agendamento configurável, circuit breaker e histórico de execuções.
🔖

Cadastro de reservas para Azure, AWS, GCP, Oracle e Multicloud. Campos adaptativos por cloud. Alerta automático no login para reservas vencendo em ≤ 90 dias com badges de severidade.
🔔
Notificações
Painel de notificações com alertas de ações com prazo próximo e reservas a vencer. Atualizado a cada 5 minutos. Destaque visual por severidade.
08
Importação de Custos Azure
Como Exportar do Azure Cost Management
1
Acesse o Azure Portal
Navegue até Cost Management + Billing > Cost Management > Cost analysis ou use a URL portal.azure.com.
2
Configure o escopo e período
Selecione a subscription desejada. Defina o período (recomendado: máximo 3 meses por arquivo para melhor performance).
3
Exporte os dados
Clique em Download e escolha o formato CSV ou Parquet. O Parquet é mais compacto e recomendado para grandes volumes. Limite máximo por arquivo: 500 MB.
4
Importe no FinOps Manager
Acesse Custos Azure > Importar, arraste o arquivo e aguarde o processamento. O sistema exibirá o progresso em tempo real. O arquivo temporário é apagado automaticamente após o processamento.
Deduplicação Automática

O sistema usa UPSERT com chave única (subscription_id, resource_id, cost_date, meter_id, charge_type, quantity). Reimportar o mesmo período não duplica registros, apenas atualiza valores.

Atenção — Valores NULL na chave de UPSERT

O PostgreSQL considera NULL ≠ NULL. Se algum campo da chave for NULL no arquivo exportado, a deduplicação pode falhar e gerar duplicatas. Execute o script migration_fix_nulls.sql caso isso ocorra.

Segurança em Produção
Configurações Obrigatórias

As seguintes configurações são essenciais antes de expor o sistema em ambiente de produção:

ConfiguraçãoAção Necessária
JWT_SECRETDefinir valor aleatório com ≥ 32 caracteres. Nunca usar o valor padrão.
MASTER_KEYDefinir valor aleatório com ≥ 32 caracteres. Protege o arquivo .finops_setup.
ALLOWED_ORIGINDefinir com o domínio exato da aplicação. Ex: https://finops.vivo.com.br
HTTPSObrigatório. Configurar via reverse proxy (nginx, Caddy, Traefik). O Node.js serve apenas HTTP.
.env criptografadoUsar node encrypt-env.js encrypt e remover o .env em texto puro do servidor.
Firewall do bancoPostgreSQL deve aceitar conexões apenas do servidor Node.js, não da internet.
Exemplo de Configuração nginx (Reverse Proxy)
server {
  listen 443 ssl http2;
  server_name finops.vivo.com.br;

  ssl_certificate     /etc/ssl/certs/finops.crt;
  ssl_certificate_key /etc/ssl/private/finops.key;

  location / {
    proxy_pass         http://127.0.0.1:3000;
    proxy_set_header   Host $host;
    proxy_set_header   X-Real-IP $remote_addr;
    proxy_read_timeout 600s; # necessário para upload de arquivos grandes
  }
}
Rate Limiting Integrado

O sistema já possui rate limiting nativo nos endpoints de autenticação: máximo de 20 requisições a cada 15 minutos por IP nos endpoints /api/auth/login e /api/auth/ad. Configure limites adicionais no nginx se necessário.

Deploy em Plataformas Cloud

O FinOps Manager pode ser implantado em qualquer plataforma que suporte Node.js e PostgreSQL. Abaixo estão as instruções para as plataformas mais utilizadas.

Railway (recomendado para início rápido)
1
Crie um projeto no Railway
Acesse railway.app, crie um novo projeto e faça o deploy do repositório ou faça upload dos arquivos via CLI.
2
Adicione o PostgreSQL
No painel do projeto, clique em + New > Database > PostgreSQL. O Railway provisiona e injeta DATABASE_URL automaticamente.
3
Configure as variáveis de ambiente
Em Variables, adicione JWT_SECRET, MASTER_KEY e ALLOWED_ORIGIN. O DATABASE_URL já é injetado automaticamente pelo banco.
4
Configure o comando de start
Em Settings > Deploy > Start Command, defina: node server.js
DATABASE_URL no Railway

O sistema reconhece automaticamente a variável DATABASE_URL e a converte para as configurações DB_*. Não é necessário definir DB_HOST, DB_PORT, etc. separadamente quando usar DATABASE_URL.

Render
1
Crie um Web Service
Em render.com, crie um novo Web Service apontando para o repositório. Defina Build Command: npm install e Start Command: node server.js.
2
Adicione um banco PostgreSQL
Crie um PostgreSQL no Render. Copie a Internal Database URL e use como DATABASE_URL nas variáveis do Web Service.
3
Configure as variáveis de ambiente
Em Environment, adicione: DATABASE_URL, JWT_SECRET, MASTER_KEY, ALLOWED_ORIGIN.
Fly.io
# Instalar CLI
curl -L https://fly.io/install.sh | sh

# Fazer login e inicializar o app
fly auth login
fly launch --name finops-manager --region gru  # gru = São Paulo

# Provisionar PostgreSQL
fly postgres create --name finops-db
fly postgres attach finops-db  # injeta DATABASE_URL automaticamente

# Definir variáveis de ambiente
fly secrets set JWT_SECRET=sua-chave-aqui
fly secrets set MASTER_KEY=sua-chave-aqui
fly secrets set ALLOWED_ORIGIN=https://finops-manager.fly.dev

# Deploy
fly deploy
Microsoft Azure — App Service + PostgreSQL Flexible Server

Solução PaaS completa sem necessidade de gerenciar VMs. O App Service gerencia escala, HTTPS e reinicialização automática.

1
Criar o Resource Group
No portal Azure (portal.azure.com) ou via CLI:
az group create --name rg-finops --location brazilsouth
2
Criar o banco de dados PostgreSQL
Acesse Criar recurso > Azure Database for PostgreSQL > Flexible Server.
Defina: nome do servidor, região (Brazil South), versão PostgreSQL 16, usuário e senha do admin.
Em Rede, selecione Acesso público e adicione o IP do App Service (ou use Integração de VNet para isolamento total).
Após criar, acesse o banco e execute: CREATE DATABASE finops_db;
3
Criar o App Service Plan e Web App
Acesse Criar recurso > Web App.
· Runtime stack: Node 18 LTS  ·  OS: Linux
· Plano: B1 (básico) para testes, P1v3 para produção
· Região: Brazil South (mesma do banco)
4
Configurar variáveis de ambiente
No Web App, acesse Configurações > Variáveis de ambiente e adicione:
VariávelValor
DATABASE_URLpostgresql://admin:senha@servidor.postgres.database.azure.com:5432/finops_db?sslmode=require
JWT_SECRETGerado com Node.js crypto (≥ 32 chars)
MASTER_KEYGerado com Node.js crypto (≥ 32 chars)
ALLOWED_ORIGINhttps://seu-app.azurewebsites.net (ou domínio customizado)
WEBSITE_RUN_FROM_PACKAGE1 (habilita deploy por ZIP)
5
Configurar o comando de startup
Em Configurações > Configuração > Configurações gerais > Comando de inicialização:
node server.js
6
Fazer o deploy dos arquivos
Via Azure CLI (método ZIP deploy — mais simples):
# Compactar os arquivos (excluindo node_modules e .env)
zip -r finops.zip . -x "node_modules/*" -x ".env" -x "uploads_tmp/*"

# Deploy via CLI
az webapp deploy --resource-group rg-finops \
  --name seu-app-finops \
  --src-path finops.zip \
  --type zip
7
HTTPS e domínio customizado
O App Service fornece HTTPS gratuito no domínio *.azurewebsites.net. Para domínio próprio, acesse Domínios personalizados > Adicionar domínio e o Azure emite o certificado SSL automaticamente via App Service Managed Certificate.
SSL no PostgreSQL Azure

O Azure Database for PostgreSQL exige SSL. A string de conexão deve incluir ?sslmode=require. O certificado CA do Azure é aceito automaticamente pelo driver pg do Node.js.

Google Cloud Platform — Cloud Run + Cloud SQL

Cloud Run executa containers serverless com escala automática para zero quando não há tráfego — ideal para ambientes de uso variável.

1
Ativar APIs necessárias
No Google Cloud Console (console.cloud.google.com) ou via CLI:
# Autenticar e configurar o projeto
gcloud auth login
gcloud config set project SEU-PROJECT-ID

# Ativar as APIs necessárias
gcloud services enable run.googleapis.com \
  sqladmin.googleapis.com \
  artifactregistry.googleapis.com \
  secretmanager.googleapis.com
2
Criar o Cloud SQL (PostgreSQL)
No console: SQL > Criar instância > PostgreSQL. Escolha PostgreSQL 16, região southamerica-east1 (São Paulo), tipo de máquina conforme carga. Crie o banco:
# Criar a instância
gcloud sql instances create finops-db \
  --database-version=POSTGRES_16 \
  --tier=db-f1-micro \
  --region=southamerica-east1

# Criar o banco e usuário
gcloud sql databases create finops_db --instance=finops-db
gcloud sql users set-password postgres --instance=finops-db --password=sua-senha
3
Criar o Dockerfile e publicar a imagem
O Cloud Run exige uma imagem Docker. Crie o arquivo Dockerfile na raiz do projeto:
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install --production
COPY . .
EXPOSE 8080
ENV PORT=8080
CMD ["node", "server.js"]
# Criar o repositório no Artifact Registry
gcloud artifacts repositories create finops-repo \
  --repository-format=docker \
  --location=southamerica-east1

# Build e push da imagem
gcloud builds submit \
  --tag southamerica-east1-docker.pkg.dev/SEU-PROJECT-ID/finops-repo/finops-manager:latest
4
Armazenar secrets no Secret Manager
Boas práticas no GCP: use o Secret Manager em vez de passar secrets como variáveis de ambiente diretamente.
# Criar os secrets
echo -n "sua-jwt-secret"    | gcloud secrets create JWT_SECRET    --data-file=-
echo -n "sua-master-key"   | gcloud secrets create MASTER_KEY    --data-file=-
echo -n "sua-db-password"  | gcloud secrets create DB_PASSWORD   --data-file=-
5
Deploy no Cloud Run
Conecte o Cloud Run ao Cloud SQL via socket Unix (sem expor o banco à internet):
gcloud run deploy finops-manager \
  --image southamerica-east1-docker.pkg.dev/SEU-PROJECT-ID/finops-repo/finops-manager:latest \
  --region southamerica-east1 \
  --platform managed \
  --allow-unauthenticated \
  --add-cloudsql-instances SEU-PROJECT-ID:southamerica-east1:finops-db \
  --set-env-vars DB_HOST=/cloudsql/SEU-PROJECT-ID:southamerica-east1:finops-db \
  --set-env-vars DB_NAME=finops_db,DB_USER=postgres \
  --set-secrets  DB_PASSWORD=DB_PASSWORD:latest \
  --set-secrets  JWT_SECRET=JWT_SECRET:latest \
  --set-secrets  MASTER_KEY=MASTER_KEY:latest \
  --set-env-vars ALLOWED_ORIGIN=https://finops-manager-xxx.run.app \
  --memory 512Mi \
  --min-instances 0 \
  --max-instances 5
Persistência no Cloud Run

O Cloud Run é stateless — cada instância começa do zero. O arquivo .finops_setup precisa estar disponível via Cloud Storage (mount com gcsfuse) ou use uma variável de ambiente com o conteúdo do setup para ambientes Cloud Run.

Amazon Web Services — Elastic Beanstalk + RDS PostgreSQL

O Elastic Beanstalk gerencia toda a infraestrutura (EC2, Load Balancer, Auto Scaling) com um único deploy, mantendo controle sobre a configuração.

1
Instalar e configurar a AWS CLI
aws configure — informe Access Key ID, Secret Access Key, região padrão (sa-east-1 para São Paulo) e formato de saída (json).
2
Criar o banco RDS PostgreSQL
Via console: RDS > Criar banco de dados > PostgreSQL. Escolha Free tier (dev) ou Multi-AZ (prod). Importante: anote o endpoint, usuário e senha. Crie o banco finops_db após provisionamento.
# Criar banco via psql após o RDS estar disponível
psql -h endpoint.rds.amazonaws.com -U postgres -c "CREATE DATABASE finops_db;"
3
Preparar o pacote de deploy
O Elastic Beanstalk exige um arquivo ZIP com o código da aplicação e um Procfile:
# Criar o Procfile na raiz do projeto
echo "web: node server.js" > Procfile

# Compactar (sem node_modules e .env)
zip -r finops-deploy.zip . \
  -x "node_modules/*" -x ".env" -x ".env.enc" -x ".env.key" \
  -x "uploads_tmp/*" -x "*.zip"
4
Criar a aplicação no Elastic Beanstalk
Via console: Elastic Beanstalk > Criar aplicação. Plataforma: Node.js 18 no Amazon Linux 2023. Ou via CLI:
# Instalar o EB CLI
pip install awsebcli

# Inicializar o projeto
eb init finops-manager \
  --platform "Node.js 18 running on 64bit Amazon Linux 2023" \
  --region sa-east-1

# Criar o ambiente de produção
eb create finops-prod \
  --instance-type t3.small \
  --database.engine postgres \
  --database.version 16 \
  --database.instance db.t3.micro \
  --database.username postgres \
  --database.password sua-senha-rds
5
Configurar variáveis de ambiente
Via console: Elastic Beanstalk > Ambiente > Configuração > Propriedades do ambiente. Ou via CLI:
eb setenv \
  JWT_SECRET=sua-chave-gerada \
  MASTER_KEY=sua-chave-gerada \
  DB_HOST=endpoint.rds.amazonaws.com \
  DB_PORT=5432 \
  DB_NAME=finops_db \
  DB_USER=postgres \
  DB_PASSWORD=sua-senha \
  ALLOWED_ORIGIN=https://finops-prod.sa-east-1.elasticbeanstalk.com \
  PORT=8080
6
Deploy e monitoramento
# Deploy do pacote ZIP
eb deploy

# Verificar logs em tempo real
eb logs --all

# Abrir no navegador
eb open

# Status do ambiente
eb status
7
HTTPS com AWS Certificate Manager
No console AWS: ACM > Solicitar certificado para seu domínio. Em seguida, no Elastic Beanstalk, vá em Configuração > Load balancer > Adicionar listener HTTPS 443 e selecione o certificado ACM. O redirecionamento HTTP → HTTPS é feito automaticamente pelo Load Balancer.
Security Groups AWS

Configure o Security Group do RDS para aceitar conexões na porta 5432 apenas do Security Group do Elastic Beanstalk. Nunca abra o RDS para 0.0.0.0/0.

Configurar como Serviço do Sistema

Para garantir que o FinOps Manager inicie automaticamente com o servidor e seja reiniciado em caso de falha, configure-o como um serviço do sistema operacional.

PM2 — Linux e Windows (recomendado)

O PM2 é um gerenciador de processos para Node.js com suporte a reinicialização automática, logs e monitoramento.

# Instalar PM2 globalmente
npm install -g pm2

# Iniciar a aplicação
pm2 start server.js --name finops-manager

# Salvar a lista de processos
pm2 save

# Registrar como serviço do sistema (gerado automaticamente para systemd/launchd/Windows)
pm2 startup
# Execute o comando que o PM2 imprimir na tela

# Comandos úteis
pm2 status                        # ver status
pm2 logs finops-manager           # ver logs em tempo real
pm2 restart finops-manager        # reiniciar
pm2 stop finops-manager           # parar
pm2 delete finops-manager         # remover
systemd — Linux (Ubuntu / Debian / CentOS)

Para servidores Linux sem PM2, crie uma unit do systemd:

# Criar o arquivo de serviço
sudo nano /etc/systemd/system/finops-manager.service

Conteúdo do arquivo:

[Unit]
Description=FinOps Manager - Vivo
After=network.target postgresql.service

[Service]
Type=simple
User=finops
WorkingDirectory=/opt/finops-manager
ExecStart=/usr/bin/node server.js
Restart=on-failure
RestartSec=10
StandardOutput=syslog
StandardError=syslog
SyslogIdentifier=finops-manager
EnvironmentFile=/opt/finops-manager/.env

[Install]
WantedBy=multi-user.target
# Ativar e iniciar o serviço
sudo systemctl daemon-reload
sudo systemctl enable finops-manager   # inicia no boot
sudo systemctl start finops-manager

# Verificar status e logs
sudo systemctl status finops-manager
sudo journalctl -u finops-manager -f   # logs em tempo real
Windows Service (NSSM)

No Windows Server, use o NSSM (Non-Sucking Service Manager) para registrar o Node.js como serviço:

1
Baixar o NSSM
Acesse nssm.cc/download e extraia o executável para C:\nssm\.
2
Registrar o serviço
Abra o PowerShell como Administrador e execute:
# Instalar o serviço
C:\nssm\nssm.exe install FinOpsManager

# Na janela que abrir, configure:
#   Path:            C:\Program Files\nodejs\node.exe
#   Startup dir:     C:\finops-manager
#   Arguments:       server.js

# Ou via linha de comando
nssm set FinOpsManager Application "C:\Program Files\nodejs\node.exe"
nssm set FinOpsManager AppDirectory "C:\finops-manager"
nssm set FinOpsManager AppParameters "server.js"
nssm set FinOpsManager Start SERVICE_AUTO_START

# Iniciar o serviço
nssm start FinOpsManager

# Verificar status
nssm status FinOpsManager
