01
Visão Geral do Sistema

O FinOps Manager é uma plataforma de gestão de custos Azure desenvolvida para a Vivo. Permite importar dados de billing do Azure, calcular e estimar o custo por hora de cada recurso, e gerar relatórios de chargeback por projeto.

Login e Autenticação

O sistema suporta três métodos de autenticação. Todos emitem o mesmo token JWT com validade de 8 horas (configurável).

MétodoComo usarObservação
Login LocalE-mail e senha cadastrados no sistemaPadrão. Senha armazenada com bcrypt.
Active Directory (AD)Clique em "Entrar com Active Directory". Usa credenciais do domínio corporativo.Requer configuração LDAP pelo administrador.
Microsoft Entra IDClique em "Entrar com Microsoft". Redireciona para o login Microsoft.Requer registro de aplicativo no Azure AD.
Sessão

O token de sessão é armazenado no browser (sessionStorage + localStorage). Ao fechar e reabrir o browser, o login é mantido até a expiração do token. Para encerrar manualmente, clique no botão de logout no menu lateral.

Limite de tentativas

O sistema bloqueia automaticamente após 20 tentativas de login em 15 minutos. Se bloqueado, aguarde 15 minutos antes de tentar novamente ou contate o administrador.

03
Dashboard e Projetos FinOps
Dashboard

A tela inicial exibe um resumo das iniciativas FinOps ativas: quantidade de projetos, ações por status, e o valor total de economia mensal esperada. Os cards de cloud mostram os custos consolidados por provedor.

Projetos

Um Projeto FinOps é uma iniciativa de otimização de custo (ex: "Migração para Reserved Instances — VM-PROD-01"). Cada projeto contém:

  • Nome e descrição — identificação da iniciativa
  • Status — Ativo, Concluído, Cancelado
  • Ações — tarefas específicas dentro do projeto
Ações FinOps

Cada ação representa uma tarefa técnica mensurável (ex: "Dimensionar VM de D4s_v3 para D2s_v3"). Os campos principais são:

CampoDescrição
DescriçãoO que será feito
StatusPendente / Em andamento / Concluída / Cancelada
Economia estimada (R$/mês)Impacto financeiro esperado
Economia realizada (R$/mês)Impacto real após execução
Responsável / PrazoQuem executa e quando
Exportação Excel

Clique em Exportar Excel para gerar um arquivo .xlsx com três abas:

  1. Sumário Executivo — visão por status e cloud com KPIs
  2. Ações Detalhadas — todas as ações com filtro automático
  3. Retorno Mensal — breakdown mês a mês da economia
04
Importação de Custos Azure

O sistema aceita arquivos de billing exportados diretamente do Azure Cost Management. Formatos suportados: CSV, Parquet, ZIP contendo CSV/Parquet.

Como exportar do Azure
1

Acesse o Azure Cost Management + Billing no portal Azure.

2

Navegue para Análise de Custo → Exportar.

3

Selecione o escopo (subscription ou grupo de gerenciamento), período e formato CSV ou Parquet.

4

Clique em Exportar e aguarde o download.

Como importar no FinOps Manager
1

Navegue para Coleta Azure no menu lateral e localize o card 📥 Importação Manual.

2

Selecione o(s) arquivo(s) — CSV, Parquet ou ZIP. Arquivos até 2 GB são suportados.

3

Clique em Importar. O processamento ocorre em background — acompanhe o progresso na barra de status.

4

Ao concluir, o sistema atualiza automaticamente os dropdowns de assinatura e grupo de recursos.

Deduplicação

O sistema detecta e ignora linhas duplicadas automaticamente. É seguro importar o mesmo arquivo mais de uma vez — não haverá dados duplicados no banco.

CSV separado por TAB

Exportações MCA recentes do Azure geram CSV com separador TAB em vez de vírgula ou ponto-e-vírgula. O sistema detecta automaticamente o separador correto.

Seleção de Assinatura e Período

Ao confirmar a assinatura, o sistema pré-preenche automaticamente um período de 30 dias retroativos à data mais recente com dados importados para aquela subscription. Isso garante que você sempre visualize um período com dados reais.

Seleção de Grupos de Recursos

O dropdown de RGs permite selecionar múltiplos grupos simultaneamente. Recursos gerenciados são selecionados automaticamente:

  • Ao selecionar um Workspace Databricks (ex: RG-WORKSPACE), os RGs filhos gerenciados (DATABRICKS-RG-*, MANAGED-RG-ADBX-* ou o padrão genérico MANAGED-RG-* — ex: MANAGED-RG-DBW-*) são marcados automaticamente.
  • Ao selecionar um cluster AKS, o RG da infraestrutura (MC_*) é marcado automaticamente.
  • Ao desmarcar o pai, os filhos são desmarcados.
Chip-bar de tipos de recurso

Após a busca, aparece uma barra com os tipos de recurso encontrados. Clique nos chips para filtrar a tabela:

VMs Discos Storage Databricks AKS SQL App Service Rede Load Balancer Key Vault Monitoramento Reservas Outros

Chip "Databricks" agrupa tanto as VMs de infraestrutura quanto as linhas de software (DBUs).

Selecionar / Desmarcar Todos

Os botões Selecionar Todos e Desmarcar Todos operam sobre todos os recursos visíveis na tabela (respeitando o filtro de tipos ativo). Recursos em grupos colapsados são incluídos na seleção mesmo não estando visíveis.

06
Tabela de Billing

A tabela principal exibe cada recurso com suas métricas de custo. Os grupos de recursos são exibidos colapsados por padrão — clique no nome do grupo para expandir.

Tipos de custo

Cada recurso é classificado em um tipo de cobrança de acordo com a unidade de medida do Azure:

TipoUnidadeExemplos
horaPor hora de usoVMs, App Service Plans, SQL Database vCores
diaPor dia de usoAlguns serviços de suporte
mêsPor mêsServiços com cobrança mensal fixa
períodoPor unidade consumidaStorage (GB), Bandwidth (GB), Databricks DBUs
reservaCompra única amortizadaReserved Instances, Savings Plans
Indicadores especiais na tabela
BadgeSignificado
⚡ amort./hVM coberta por Reserva ou Savings Plan. O custo de billing é R$0 (já pago na compra da reserva); o valor exibido é o custo amortizado real via effective_price.
⚡ DatabricksVM pertencente a um cluster Databricks. O custo/h exibido é a contribuição proporcional da VM no cluster.
⚡ /DBU cobradoLinha de software Databricks (DBU). Exibe o custo por DBU (unidade de processamento Databricks).
R$/GB (laranja)Custo por gigabyte para recursos de storage/bandwidth. Linha secundária abaixo do custo total.
Custo por unidade nativa (RN-006)

Para todos os recursos, o sistema calcula o custo real por unidade de medida nativa (custo_billing ÷ quantidade). Isso fornece o preço efetivo por hora, por GB, por DBU, etc. — independente de descontos, reservas ou período. É o valor mais confiável para auditar a fatura Azure.

08
Horário Livre

O Horário Livre permite descontar automaticamente as horas fora do expediente de trabalho do custo total do período. Útil para cobranças de ambiente de desenvolvimento/homologação que ficam inativos à noite e nos finais de semana.

Como configurar
1

No modo Período, localize o card Horário Livre abaixo da tabela.

2

Clique no toggle para ativar.

3

Defina o horário de início e fim do período sem cobrança (ex: 18:00 às 08:00).

4

Marque os dias da semana aplicáveis (normalmente sábado e domingo para fins de semana).

5

O resumo atualiza em tempo real: "Xh totais → −Yh livres → Zh cobradas".

Salvar como padrão

Clique em ★ Salvar como padrão para que as configurações de horário livre sejam lembradas automaticamente nas próximas sessões. Use ↺ Limpar para remover o padrão salvo.

Portal Público

No portal público, se o administrador tiver configurado um horário livre padrão, os campos aparecem preenchidos e bloqueados (somente leitura). O texto "⚙ Configurado pelo administrador" é exibido. Se o administrador não configurou, o usuário pode definir livremente.

Reservas Cloud

O módulo de Reservas controla instâncias reservadas (Reserved Instances) e compromissos de uso (Savings Plans) em múltiplas clouds, com alertas automáticos de vencimento.

Cadastrar uma reserva
1

Acesse Reservas Cloud no menu lateral e clique em + Nova Reserva.

2

Selecione a Cloud (Azure, AWS, GCP, Oracle, Multicloud).

3

Preencha: nome da reserva, tipo de escopo (Subscription/Resource Group), instância, prazo (1 ou 3 anos), custo total e data de início.

4

A data de vencimento é calculada automaticamente com base na data de início e no prazo.

5

Clique em Salvar.

Alertas de vencimento

A cada login, o sistema verifica automaticamente reservas ativas com vencimento nos próximos 90 dias e exibe um popup de alertas:

PrazoSeveridade
Expirada (vencida)🔴 Expirada
0 a 30 dias🟠 Crítico
31 a 60 dias🟡 Atenção
61 a 90 dias🔵 Aviso

Para parar de receber alertas de uma reserva, atualize o status para Renovada ou Cancelada.

10
Coleta Automática — Azure

A Coleta Automática elimina a necessidade de exportar e importar arquivos CSV manualmente. O sistema busca os dados de billing diretamente da Azure Management API usando Service Principals configurados pelo administrador. A tela fica em Coleta Azure, no menu lateral.

Configurar um Service Principal
1

No Azure, crie um App Registration e anote o Tenant ID, Client ID e gere um Client Secret.

2

Atribua as roles Reader e Storage Blob Data Reader ao Service Principal nas subscriptions desejadas.

3

No FinOps Manager, acesse Coleta Azure → Service Principals → + Adicionar SP.

4

Informe nome, Tenant ID, Client ID e Client Secret, o modo de coleta (Assinaturas específicas ou por Billing Account/Profile) e marque Ativo. As credenciais são encriptadas com AES-256 antes de serem salvas.

5

Clique em Testar para verificar a conexão antes de salvar.

6

No card Agendamento, defina horário e dias de execução automática, e a granularidade (7/15/30 dias ou período livre).

Coleta via Storage Account (alternativa)

Para ambientes com exportação automática do Azure Cost Management já configurada para uma Storage Account, cadastre a conta em Storage Accounts (nome da conta, container, prefixo do blob) vinculada a um Service Principal com role Storage Blob Data Reader. O agendador varre os blobs novos periodicamente, sem precisar de acesso via Management API.

Cobertura, Histórico e Diagnóstico

O card Cobertura por Mês mostra uma grade com o percentual de dias com dados por subscription/mês (verde ≥95%, laranja 70–94%, vermelho <70%) — clique numa célula para detalhar por subscription, ou use os botões ▶ Coletar Agora/Agendar Pendente diretamente na célula. Histórico de Execuções lista cada coleta com origem (⏰ agendada / 👤 manual), duração, contagem de registros e um selo de Validação (✅ OK / ⚠ Aviso / ❌ Falha) — clique em "Revalidar" para reprocessar a checagem de integridade de uma execução antiga. Diagnóstico e Limpar Dados (expurgo por período, arquivo ou tudo) ficam disponíveis para investigar e corrigir problemas de importação.

Circuit Breaker

O sistema possui proteção automática contra falhas consecutivas: após 3 erros seguidos, a coleta é pausada por 5 minutos antes de tentar novamente. Isso evita sobrecarga na Azure API em caso de problemas de conectividade.

11
Coleta Automática — Databricks

O billing do Azure nunca traz identidade de usuário nem o catálogo de produto interno do Databricks (ex: distinguir uso pago de GENIE_FREE_USAGE) — essa granularidade só existe nas System Tables do próprio Databricks (system.billing.usage + system.billing.list_prices, no Unity Catalog), uma fonte de dados separada, com autenticação própria. A tela fica em Coleta Azure → card "Coleta Databricks", ao lado da coleta Azure — arquitetura equivalente (conexão → coleta agendada → tabela própria → dashboard).

Dois modos de autenticação
ModoQuando usarRequer
OAuth M2M (Service Principal de conta)Padrão recomendado — não amarra a coleta a uma pessoaAcesso de Account Admin na conta Databricks para criar o Service Principal
PAT (Personal Access Token)Alternativa quando não há Account Admin disponívelUm token gerado por qualquer usuário/Service Principal de workspace com grants nas System Tables

Os dois modos leem exatamente as mesmas tabelas — a única diferença é o nível da credencial. Funcionalidades que chamam APIs de nível de conta (Quotas Genie — ver Seção 14) exigem obrigatoriamente OAuth M2M; um PAT não serve para elas.

Configurar conexão — modo OAuth M2M
1

No console da conta Databricks, um Account Admin cria um Service Principal a nível de conta e gera um Client Secret.

2

Em Catalog Explorer → System Tables, um Account Admin habilita explicitamente os schemas necessários — não vêm habilitados por padrão em nenhuma conta.

3

Conceda ao Service Principal USE SCHEMA + SELECT em system.billing.usage e system.billing.list_prices.

4

No FinOps Manager, Coleta Databricks → + Nova Conexão: selecione modo OAuth M2M e informe Account ID, Client ID, Client Secret, o host de um workspace (usado para executar as queries) e o ID de um SQL Warehouse.

5

Marque Ativo e, se for a única conexão, Padrão.

Configurar conexão — modo PAT
1

Gere um Personal Access Token em qualquer workspace (User Settings → Developer → Access Tokens), usando um usuário ou Service Principal de workspace com USE SCHEMA + SELECT nas mesmas duas tabelas acima.

2

No FinOps Manager, selecione modo PAT — os campos Account ID/Client ID/Client Secret somem; preencha apenas Token, host do workspace e ID do SQL Warehouse.

Não existe "token da API" avulso

No modo OAuth M2M não há token para colar manualmente — Client ID + Client Secret são as credenciais do Service Principal, e o sistema troca essas credenciais por um token de acesso automaticamente, a cada execução.

Testar Conexão

O botão Testar não faz apenas SELECT 1 — ele verifica individualmente cada System Table exigida (system.billing.usage, system.billing.list_prices). O erro retornado aponta a causa exata: TABLE_OR_VIEW_NOT_FOUND significa que o schema não foi habilitado na conta (passo 2 acima); PERMISSION_DENIED/ACCESS_DENIED significa que falta o grant na credencial (passo 3).

Um segundo grupo, opcional, testa system.lakeflow.job_run_timeline e system.lakeflow.jobs — schema separado de system.billing, precisa ser habilitado à parte por um account admin. Se esse grupo falhar, o custo por recurso continua funcionando normalmente; só o card Execuções de Job (Seção 12) fica vazio.

Agendamento e coleta manual

Assim como na Coleta Azure, configure horário/dias de execução e granularidade no card de Agendamento, ou dispare uma coleta pontual em Coletar Agora informando o intervalo de datas. O progresso aparece em tempo real no monitor da tela.

Importação Manual (CSV)

Para quem não tem/não quer configurar coleta automática, o card 📥 Importação Manual aceita um .csv (até 100 MB) com os mesmos nomes de campo internos que a coleta ao vivo produz: workspace_id, sku_name, produto_origem, usage_date, usage_unit, usage_quantity, usuario, preco_unitario, custo_estimado e, opcionalmente, usage_metadata/custom_tags (string JSON). Apenas workspace_id, sku_name e usage_date são obrigatórios — linhas sem esses três campos são ignoradas e contabilizadas no resultado.

Limpar Dados (Expurgo)

O botão 🗑 Limpar Dados, no card Histórico de Execuções, remove registros de databricks_consumo por workspace, por período, ou tudo — útil para descartar dados de teste antes de uma coleta de produção. Exige confirmação de preview antes de habilitar o botão de confirmar.

Granularidade por recurso

Cada linha coletada representa um recurso individual (job, cluster, workspace, SKU, tags) — não um total agregado por dia. Isso permite que dois recursos com tags diferentes (ex: dois jobs de projetos distintos) rodando no mesmo dia/workspace/SKU sejam contabilizados corretamente, sem misturar o custo de um no outro.

12
Dashboard Databricks

Acesse pelo menu lateral Databricks, um grupo com 3 sub-abas: Dashboard, Orçamentos e Anomalias e Quotas. Alternar entre elas não recarrega a página — o filtro de período e os dados ficam por aba.

Aba Dashboard

Mostra KPIs do período selecionado, um gráfico de Tendência Mensal em barras com previsão de 3 meses (regressão linear sobre o histórico, exibida com textura hachurada + borda tracejada para diferenciar do custo real), e seis rankings (Top 10 cada): Por Workspace, Por SKU, Por Usuário, Por Job, Por Cluster e Por Warehouse — os três últimos vêm do mesmo dado já coletado (usage_metadata), sem nenhuma coleta adicional.

Execuções de Job — tempo e custo

Logo abaixo dos rankings, uma tabela lista as execuções recentes de Job (mais recentes primeiro, até 200 por período): Job, Run, Início, Duração, Status (✅ Sucesso / ❌ Falhou / ⏱ Timeout / ⊘ Cancelado, entre outros) e Custo. Clicar num job em "Por Job" também filtra esta tabela.

A duração e o status vêm de um schema diferente do usado para custo (system.lakeflow, ver Seção 11) — por isso é possível ver o custo por job funcionando normalmente enquanto esta tabela fica vazia, se esse schema não estiver habilitado na conta.

Custo "—" não é custo zero

Nem toda execução tem custo correlacionável: o Databricks só associa o identificador da execução ao billing quando o job roda em job compute ou serverless compute — jobs em cluster all-purpose não têm essa correlação. Nesses casos a coluna Custo mostra — (sem dado), nunca R$ 0,00 (que sugeriria "rodou de graça").

DBUs Consumidos (pagos vs. free)

Um card específico mostra o volume em DBUs (a unidade nativa de processamento Databricks), separado entre free-tier e pago. Diferente do card de custo em R$ — onde o free-tier sempre aparece como R$ 0,00 por definição —, este card revela o volume real consumido de graça, informação que fica invisível olhando só o valor financeiro.

Drill-down (filtro cruzado)

Clique em qualquer item de um ranking (um workspace, uma SKU, um usuário, um job, um cluster ou um warehouse) para reconsultar todos os outros gráficos já escopados a esse item — igual a uma ferramenta de BI. Um chip "Detalhando por: ..." aparece abaixo do seletor de período; clique nele ou em "Limpar filtros" para remover. Clicar de novo no mesmo item remove o filtro (toggle).

Ponto de atenção (⚠️) nos rankings

Quando o motor de detecção de anomalias (Seção 13) encontra um workspace ou usuário fora do padrão, o item correspondente nos rankings Por Workspace/Por Usuário ganha um ícone ⚠️ ao lado do nome. Clique no ícone para navegar direto para a aba Orçamentos e Anomalias e ver o detalhe (Z-score, % de crescimento).

13
Governança e Anomalias (Databricks)

Sub-aba Orçamentos e Anomalias, dentro do menu Databricks. Reúne orçamentos internos (calculados sobre o consumo já coletado) e a detecção automática de padrões fora do esperado.

Orçamentos internos

Diferente das Quotas Genie (Seção 14), estes orçamentos são calculados pelo FinOps Manager sobre databricks_consumo — apenas alertam, nunca bloqueiam nada no Databricks.

1

Clique em + Novo Orçamento.

2

Defina o escopo: Global (toda a conta), por Workspace, ou por Tag (escolha uma chave já vista nos dados, ex: projeto/time/centro_custo, e um valor).

3

Informe o valor mensal (R$) e, opcionalmente, ajuste os thresholds de Atenção e Crítico (padrão 75% e 90%).

4

Salve. Um popup de alerta aparece automaticamente ao entrar no sistema quando o consumo do mês corrente ultrapassa o threshold configurado — cada alerta pode ser dispensado individualmente na sessão.

Detecção de Anomalias

Dois tipos de anomalia são calculados automaticamente, sem configuração:

TipoMétodoThreshold

Quotas Genie (Databricks)

Sub-aba Quotas, dentro do menu Databricks. Diferente dos Orçamentos internos (Seção 13, só alerta), as Quotas Genie usam a Budgets API nativa do Databricks (nível de conta) — o limite é aplicado pelo próprio Databricks, não pelo FinOps Manager, e pode efetivamente bloquear o acesso ao Genie quando o teto é cruzado.

Requer Account Admin

Esta feature só funciona com uma conexão em modo OAuth M2M marcada como padrão (Seção 11) — PAT não tem o escopo de nível de conta necessário. Sem essa conexão, a tela mostra um erro explicando exatamente o que falta.

Criar uma quota
1

Clique em + Nova Quota Genie.

2

Informe um nome, e opcionalmente restrinja por Workspace IDs (lista separada por vírgula) e/ou tags (pares chave/valor).

3

Defina o limite em US$ (a Budgets API do Databricks trabalha em dólar, diferente do restante do sistema, que é BRL).

4

Escolha o escopo: Compartilhado (soma de todos) ou Por usuário (necessário para configurar limites individuais — ver abaixo).

5

Escolha a ação: Alertar por e-mail ou Bloquear acesso ao Genie. A segunda exige marcar um checkbox explícito de confirmação antes de habilitar o botão de salvar.

Limites individuais por usuário/grupo (overrides)

Disponível apenas com escopo Por usuário — a documentação oficial do Databricks confirma que overrides são ignorados em orçamentos de escopo compartilhado. Busque por e-mail exato (usuário) ou nome exato (grupo) — a busca localiza o principal_id real via SCIM da conta Databricks — e defina um valor (US$) próprio para aquele usuário/grupo. Limite de 20 overrides por quota.

Editar e Excluir

Use o botão ✏ Editar na listagem para alterar uma quota já criada (nome, workspaces, tags, limite, escopo, ação, overrides) — a edição substitui a configuração inteira. Ao editar uma quota de bloqueio, o checkbox de confirmação precisa ser marcado novamente, mesmo que a quota já bloqueasse antes. Excluir remove a quota da conta Databricks imediatamente.

🧪 Modo demonstração

Quando não há nenhuma conexão OAuth M2M configurada como padrão, a tela exibe um banner "Modo demonstração" e opera sobre dados fictícios (persistidos localmente) — permite validar a estrutura de criar/editar/excluir quotas antes de ter acesso de Account Admin. Assim que uma conexão OAuth M2M real for marcada como padrão, a tela passa a usar a Budgets API real automaticamente, sem nenhuma ação manual.

Portal Público

O Portal Público é uma versão sem autenticação da Calculadora de Custos. Permite que usuários externos (sem conta no sistema) consultem custos Azure de subscriptions autorizadas pelo administrador.

Ativação (apenas Administradores)
1

Acesse Configurações → Portal Público.

2

Ative o toggle Portal Ativo.

3

Configure as Subscriptions permitidas — apenas essas serão visíveis no portal.

4

Defina opcionalmente: título, descrição, taxa de imposto, taxa de condomínio, horário livre e domínios aceitos para identificação.

5

Clique em Salvar. O portal estará disponível em /portal.html.

Identificação de usuário no portal

Se o administrador ativou a solicitação de identificação ou configurou domínios aceitos, o usuário deverá informar nome e e-mail antes de acessar a calculadora. O sistema valida o domínio do e-mail.

Configurações fixas no portal

Campos configurados pelo administrador (taxa de imposto, taxa de condomínio, horário livre) aparecem preenchidos e bloqueados no portal público — o usuário vê os valores mas não pode alterá-los. Campos não configurados pelo admin ficam editáveis pelo usuário.

Regras de Negócio — Referência

Esta seção detalha as regras de cálculo aplicadas pelo sistema. É útil para auditores, analistas técnicos e equipes de FinOps que precisam validar os valores calculados.

RN-006 — Custo por unidade nativa

Fórmula: custo_billing ÷ quantidade_total

Fornece o preço efetivo por hora (VMs), por GB (storage), por DBU (Databricks), por 10K transações, etc. É o valor ideal para auditar a fatura e verificar se corresponde ao preço negociado.

RN-007 — Amortizado (RI / Savings Plan)

VMs com Reserved Instance ou Savings Plan têm cost_in_billing_currency = 0. O sistema usa effective_price × qty para calcular o custo amortizado real (Azure distribui o valor da reserva hora a hora).

Badge: ⚡ amort./h na tabela.

RN-DB-001 — Taxa de cluster Databricks

Clusters Databricks têm múltiplas VMs rodando em paralelo. O custo por hora do cluster é: C_total_rg ÷ H_driver, onde H_driver = soma do uptime diário do driver (para capturar múltiplas sessões).

Válido quando: ≥ 24h de driver e ≥ 2 recursos distintos.

Estimativa de Pico (v2.1)

O sistema identifica o dia com maior billing no período selecionado e usa esse valor como base para a estimativa "pior caso". Útil para dimensionar custos em ambientes variáveis (autoscale).

Indicador: ⚠ laranja nos cards de estimativa.

Período padrão (30 dias)

Ao selecionar uma subscription, o sistema pré-preenche automaticamente os últimos 30 dias de dados reais disponíveis no banco (data_mais_recente − 30 dias). Garante sempre um período válido.

RGs Gerenciados (auto-seleção)

Ao selecionar um workspace Databricks, seus RGs filhos (DATABRICKS-RG-*, MANAGED-RG-ADBX-* ou o padrão genérico MANAGED-RG-* — ex: MANAGED-RG-DBW-*) são marcados automaticamente. O mesmo vale para clusters AKS e seus RGs de infraestrutura (MC_*).

Dois streams de billing Databricks

Databricks gera duas linhas de custo independentes por workspace:

StreamOnde apareceServiço AzureIndicador
Infraestrutura (VMs)RG gerenciado DATABRICKS-RG-* / MANAGED-RG-*Microsoft.Compute (VMs)⚡ Cluster/h (azul)
Software (DBUs)RG do workspace (definido pelo usuário)Microsoft.Databricks⚡ /DBU cobrado (azul)

O custo total real de um cluster = custo de infraestrutura + custo de software DBU. Os dois valores devem ser somados para obter o custo completo do workspace.
