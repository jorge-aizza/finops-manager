Por que o período pré-preenchido não é hoje? Calculadora ⌄

O sistema pré-preenche automaticamente os últimos 30 dias de dados reais disponíveis no banco para a assinatura selecionada. Isso garante que você sempre visualize um período com dados importados — e não um período vazio.

Se a importação mais recente for de 30/06, o período padrão será 01/06 → 30/06. Importe dados mais recentes para que o período atualize.

O que significa o badge ⚡ amort./h em uma VM? Calculadora ⌄

Indica que a VM está coberta por uma Reserved Instance ou Savings Plan. Nesse caso, o custo de billing diário é R$ 0 (pois o valor foi pago antecipadamente na compra da reserva).

O valor exibido com o badge ⚡ é o custo amortizado, calculado via effective_price × quantidade — o Azure distribui o valor total da reserva proporcionalmente pelas horas de uso. Esse valor representa o custo real hora a hora da reserva.

Ao selecionar um RG pai de Databricks, o RG filho some do dropdown. É normal? Calculadora ⌄

Sim, é o comportamento esperado. Ao selecionar um workspace Databricks (ex: RG-WORKSPACE), os RGs filhos gerenciados (DATABRICKS-RG-*) são marcados automaticamente e movidos para o topo da lista como selecionados.

Da mesma forma, selecionar um cluster AKS marca automaticamente seu RG de infraestrutura (MC_*). Ao desmarcar o pai, os filhos são desmarcados.

O que é o indicador ⚠ Pico/h (laranja) na estimativa? Calculadora ⌄

Indica que a estimativa está usando o custo do dia de maior billing do período, em vez da média histórica. É o cenário de "pior caso".

Útil para ambientes com autoscale (VMs que sobem e descem automaticamente): a média pode subestimar o custo real em dias de pico de uso.

O pico é carregado em background ao abrir o painel de estimativa. Se ainda não carregou, os cards mostram a média — aguarde alguns segundos.

Por que alguns recursos aparecem com R$/GB em laranja? Calculadora ⌄

Recursos de storage, bandwidth e discos são cobrados por volume consumido (tipo período), não por hora. A linha em laranja mostra o custo por unidade nativa (R$/GB, R$/10K transações, etc.).

Esse valor é calculado pela fórmula: custo_total ÷ quantidade_total, fornecendo o preço efetivo por GB no período — ideal para auditar se corresponde ao preço contratado.

Como funciona o Horário Livre? Calculadora ⌄

O Horário Livre desconta automaticamente as horas fora do expediente do custo total do período. Útil para ambientes de desenvolvimento que ficam inativos à noite e nos finais de semana.

Como configurar: ative o toggle no card Horário Livre → defina os horários de início e fim do período sem cobrança → marque os dias da semana aplicáveis.

O resumo mostra: "Xh totais → −Yh livres → Zh cobradas".

Use ★ Salvar como padrão para memorizar a configuração entre sessões.

O que é o card Horas Adicionais (⏱)? Calculadora ⌄

O card Horas Adicionais estima o custo incremental de usar os recursos por horas extras além do período analisado — útil para calcular o impacto de trabalho adicional ou horas de projeto fora do intervalo importado.

Como usar: informe a quantidade de horas extras por dia e o número de dias do projeto. O sistema exibe automaticamente uma coluna ⏱ Adicional (laranja) na tabela com o custo extra por recurso e um banner de resumo acima da tabela.

Disponível apenas no modo Período, após o primeiro Buscar. Recursos com cobrança de Reserva (🔒) mostram R$ 0 adicional — o custo já está pago na compra da reserva.

O que é o custo 🔒 Fixo/mês no painel de estimativa? Calculadora ⌄

Serviços com cobrança mensal fixa (tipo mês) têm custo independente das horas de uso. O slider de horas não altera o valor estimado desses recursos.

Exemplos: alguns serviços de suporte Azure, licenças mensais, planos fixos.

A tabela demora para aparecer com muitos recursos. É problema? Calculadora ⌄

Não é problema. Com muitos recursos (ex: 30.000+), o sistema usa renderização em lotes para evitar travar o browser: os primeiros grupos aparecem em ~32ms e o restante carrega progressivamente em segundo plano via animação de frames.

O painel de estimativa usa carregamento automático por scroll (IntersectionObserver) — role para baixo para carregar mais cards automaticamente.

Posso importar o mesmo arquivo mais de uma vez? Importação ⌄

Sim. O sistema faz deduplicação automática usando uma chave composta de 6 campos do billing Azure. Importar o mesmo arquivo múltiplas vezes não gera dados duplicados no banco.

A deduplicação depende de todos os campos-chave estarem preenchidos. Arquivos com campos em branco podem gerar duplicatas — use os arquivos originais exportados do Azure Cost Management.

Quais formatos de arquivo são suportados? Importação ⌄

O sistema aceita:

  • CSV — separador vírgula, ponto-e-vírgula ou TAB (detectado automaticamente)
  • Parquet — formato binário comprimido do Azure Cost Management
  • ZIP — contendo um ou mais arquivos CSV ou Parquet

Tamanho máximo: 2 GB por arquivo.

Exportações MCA recentes do Azure geram CSV com separador TAB. O sistema detecta automaticamente — não é necessário converter.

A importação ficou parada. O que fazer? Importação ⌄

A importação ocorre em background no servidor. Arquivos grandes (centenas de MB) podem levar vários minutos. A barra de progresso atualiza periodicamente.

Se a barra parou de atualizar por mais de 10 minutos:

  1. Verifique os logs do servidor (pm2 logs finops-manager)
  2. Confirme que há espaço em disco suficiente no diretório uploads_tmp/
  3. Para arquivos muito grandes, considere usar a Coleta Automática via Azure Storage — mais eficiente para arquivos acima de 500 MB
Como adicionar um novo usuário ao sistema? Administração ⌄

Acesse Configurações → Usuários → + Novo Usuário. Preencha nome, e-mail, senha e perfil (Administrador, Analista ou Visualizador).

Se o sistema estiver integrado com Active Directory ou Microsoft Entra ID, os usuários podem fazer login com as credenciais corporativas sem precisar de cadastro manual — apenas o primeiro login cria o registro no banco.

O que acontece se o MASTER_KEY mudar? Administração ⌄

O MASTER_KEY é usado para criptografar o arquivo .finops_setup e as credenciais dos Service Principals. Se a chave mudar após a configuração inicial, o arquivo de configuração ficará ilegível e o wizard de setup será exibido novamente.

Sempre guarde o MASTER_KEY em um cofre seguro (ex: Azure Key Vault, LastPass, Bitwarden corporativo). Nunca mude a chave em produção sem um plano de backup dos dados criptografados.

Como configurar a Coleta Automática de custos? Administração ⌄

A Coleta Automática usa Service Principals do Azure para buscar dados de billing sem upload manual:

  1. No Azure, crie um App Registration e atribua as roles Reader + Storage Blob Data Reader
  2. No FinOps Manager: Configurações → Coleta Automática → + Adicionar SP
  3. Informe Tenant ID, Client ID e Client Secret
  4. Clique em Testar credenciais para validar
  5. Configure o agendador (horário e dias)
Como sincronizar a Price List do Azure? Administração ⌄

Acesse Configurações → Price List → Sincronizar. O sistema busca automaticamente todos os preços de tabela da API pública do Azure Retail Prices (preços em USD).

A sincronização apaga e recria todos os dados da Price List. Se você importou uma Price List em BRL via CSV, os dados BRL serão perdidos na próxima sincronização USD. Para manter BRL, reimporte o CSV após a sincronização.

Como parar de receber alertas de uma reserva vencida? Reservas ⌄

O popup de alertas aparece automaticamente a cada login para reservas com vencimento nos próximos 90 dias. Para parar os alertas, atualize o status da reserva para Renovada ou Cancelada em Reservas Cloud → editar.

Posso registrar reservas de outras clouds além do Azure? Reservas ⌄

Sim. O módulo de reservas suporta: Azure, AWS, GCP, Oracle Cloud e Multicloud. Cada cloud tem campos específicos adaptados ao seu modelo de reserva (ex: AWS usa Account, GCP usa Project).

Como ativar o Portal Público? Portal Público ⌄

Apenas administradores podem ativar o Portal Público:

  1. Acesse Configurações → Portal Público
  2. Ative o toggle Portal Ativo
  3. Selecione as Subscriptions permitidas — obrigatório; sem isso, nenhum dado é exposto
  4. Configure opcionalmente: título, descrição, taxas padrão, horário livre e domínios aceitos
  5. Clique em Salvar

O portal ficará disponível em /portal.html do mesmo domínio do sistema.

Como restringir quem pode acessar o portal público? Portal Público ⌄

Duas opções disponíveis nas configurações do portal:

  • Domínios aceitos — apenas e-mails do(s) domínio(s) configurado(s) podem acessar (ex: vivo.com.br). Um formulário de identificação é exibido antes de entrar.
  • Solicitar identificação — sempre pede nome e e-mail, mas sem restrição de domínio. O acesso é registrado no log de acessos do portal.

Se nenhuma das opções estiver configurada, o portal é de acesso livre (sem login).

Por que o custo do Databricks aparece em dois RGs diferentes? Databricks ⌄

O Databricks gera dois streams de billing independentes por workspace:

  • Infraestrutura (VMs) — aparece no RG gerenciado criado automaticamente pelo Azure: DATABRICKS-RG-* ou variantes como MANAGED-RG-DBW-*, MANAGED-RG-ADBX-*. Serviço: Microsoft.Compute.
  • Software (DBUs) — aparece no RG do workspace definido pelo usuário. Serviço: Microsoft.Databricks.

O custo total real = custo de infraestrutura + custo de software DBU. Os dois devem ser somados para ter o custo completo do workspace.

O que significa o ⚡ Cluster/h no card de estimativa do Databricks? Databricks ⌄

Um cluster Databricks tem múltiplas VMs rodando em paralelo (driver + N workers). O custo por hora real não é o de uma VM individual, mas a soma de todas as VMs ativas simultaneamente.

⚡ Cluster/h = custo total do RG ÷ horas de uptime do driver. Representa o custo por hora do ambiente Databricks ativo, independente de quantas VMs estão no cluster.

Para job clusters (VMs criadas a cada sessão), o sistema soma o uptime diário para capturar múltiplas execuções no mesmo dia — mais preciso que usar apenas a sessão mais longa.

O que é DBU e como interpretar o custo /DBU? Databricks ⌄

DBU (Databricks Unit) é a unidade de medida do software Databricks. Cada tipo de workload (All-Purpose, Jobs, Delta Live Tables, SQL Warehouse) consome DBUs a taxas diferentes.

O custo ⚡ /DBU cobrado é calculado como: custo_total_software ÷ total_DBUs_consumidos no período. Permite verificar se a taxa por DBU corresponde ao contrato.
